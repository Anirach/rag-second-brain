## Google Drive Organization Pattern (REMEMBER)

When uploading project deliverables to Google Drive:
1. **Always create a subfolder** named after the project/paper
2. Use `--folder` option: `python3 gdrive/gdrive_upload.py file.pdf --folder "Project_Name"`
3. Or organize after upload: `python3 gdrive/gdrive_upload.py --organize "Folder_Name" file1 file2 ...`

**Structure pattern:**
```
📁 ArthurBotData/
└── 📁 Project_Name/
    ├── 📄 paper.pdf
    ├── 📄 paper.docx
    ├── 📄 main.tex
    ├── 📁 code/
    └── 📄 README.md
```

Never dump files in root - always organize into project folders!

## Journal Review & Revision Workflow Added

**New capability:** Academic Team can now handle the full publication lifecycle:

1. **Initial Submission** → Paper complete with verification
2. **After Review** → User shares reviewer comments
3. **Revision** → Academic Team:
   - Parses all reviewer comments
   - Addresses each point (Accept/Rebut)
   - Revises paper accordingly
   - Generates "Response to Reviewers" letter
   - Re-verifies everything
4. **Re-submit** → Loop until accepted

**Trigger command:**
```
Arthur, revise the paper "[Title]" based on these reviewer comments:
[paste reviews]
Paper folder: [folder name]
```

**Deliverables per revision round:**
- Revised paper (clean + tracked changes)
- Response to Reviewers letter
- Revision log
- Re-verification results
