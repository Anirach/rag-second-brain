**Critical fix — emoji corruption:**
After generating PPTX, MUST post-process to replace high Unicode (emoji above U+FFFF) with XML numeric character references (`&#xHHHHH;`):
```python
import zipfile, re
def fix(b):
    t = b.decode('utf-8')
    return re.sub(r'[\U00010000-\U0010FFFF]', lambda m: f'&#x{ord(m.group(0)):X};', t).encode('utf-8')
with zipfile.ZipFile('input.pptx','r') as zi:
    with zipfile.ZipFile('output.pptx','w',zipfile.ZIP_DEFLATED) as zo:
        for i in zi.infolist():
            d = zi.read(i.filename)
            if i.filename.endswith('.xml') or i.filename.endswith('.rels'):
                d = fix(d)
            zo.writestr(i, d)
```
Without this fix, PowerPoint shows "needs repair" dialog.

### PPTX Layout Rule: NO TEXT OVERFLOW (CRITICAL)
**Slide height is 5.63" (16:9 layout). Usable content area: y=1.1 to y=5.0 (~3.9" total).**

Rules to prevent overflow:
1. **Max content bottom: y + h ≤ 4.95** (leave room for tagline at 4.95)
2. **Without tagline: y + h ≤ 5.3**
3. **Code blocks**: Max ~8 lines visible at fontSize 9. Split long code into 2 columns.
4. **Cards**: Keep body text concise. Max 4-5 bullet lines per card.
5. **Stacking rule**: Before placing an element, calculate: previous_y + previous_h + gap = next_y. Verify next_y + next_h ≤ limit.
6. **Long content → split across slides** or use 2-column layout instead of vertical stacking.
7. **Never put more than 3 vertical blocks** (card + code + card) without checking total height.

### HA Data De-Identification Rule (CRITICAL — PERMANENT)
**Problem:** Raw HA database queries send hospital names, codes, scores, and staff data to Anthropic API. This is a data leak risk.
**Rule:** ALL HA query results MUST be de-identified before entering the LLM context.
**De-ID approach:**
1. Run psql query → save raw result to local file (never printed to stdout)
2. Python de-ID script strips/masks: hospital_name, old_hospital_name, hospital_english_name, hospital_code, internal_code, leader_position, organization_name, notes, any person names
3. Replace with: Hospital_001, Hospital_002, etc. (consistent mapping within session)
4. Only the de-identified version gets printed/returned to the LLM
5. Aggregated queries (COUNT, GROUP BY) are safe without de-ID
6. Schema/column queries are safe without de-ID
