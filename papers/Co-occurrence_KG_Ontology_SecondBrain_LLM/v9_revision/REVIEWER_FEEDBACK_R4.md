# Reviewer Feedback — Round 4

## Paper: "Co-occurrence, Sequence and Knowledge Graph with Ontology as a Second Brain for AI-LLM"

### Overall Assessment: Score 4.4 (Down from 5.6)

The score dropped significantly due to **credibility-destroying errors** in v8. While the core ideas remain promising, the execution errors undermine trust in all reported numbers.

---

## Critical Issues (Score-Blocking)

### 🔴 Issue 1: Cost Calculation Wrong by 1000×

**Location:** Section 3.4 (Oracle Labeling)

**Problem:**
> v8 claims: "2.7M calls × ~1k tokens × $0.05/1k = $135"

This is mathematically wrong:
- 2.7M calls × 1k tokens = 2.7 BILLION tokens
- At $0.05/1k: 2.7B / 1000 × $0.05 = **$135,000** NOT $135

The calculation error is off by exactly 1000×. This is not a typo—it reveals the authors did not sanity-check their numbers.

**Impact:** Destroys credibility. If this basic calculation is wrong, how can we trust throughput claims, latency measurements, or ablation results?

**Required Fix:** Recalculate ALL costs with:
1. Actual GPT-3.5 pricing (June 2023: $0.0015/1k input, $0.002/1k output)
2. If full 2.7M labeling was done, acknowledge the real cost (~$2k-3k)
3. If subsampling was used, document the exact strategy

---

### 🔴 Issue 2: Training Throughput Claims Unrealistic

**Location:** Section 4.3 (Training Details)

**Problem:**
> v8 claims: "42k tokens/sec with QLoRA 4-bit on 4×A100"

Published QLoRA benchmarks (Dettmers et al., 2023) show:
- Single A100-80GB: 6-12k tokens/sec for 70B models
- 4×A100 with gradient accumulation: ~24-48k tokens/sec (with overhead)

42k is on the high end but plausible. However, with the cost error above, I cannot trust this number without verification.

**Required Fix:**
1. Cite specific benchmark comparisons (Dettmers et al., HuggingFace PEFT)
2. Report wall-clock training times as cross-check
3. If numbers were estimated rather than measured, say so

---

### 🔴 Issue 3: Cross-Attention Module Conflation

**Location:** Section 3.5 (Training Pipeline)

**Problem:** The paper uses "cross-attention" in multiple contexts without clear delineation:
1. "Cross-attention enrichment on 30 candidates" — is this before or after gating?
2. "Cross-attention fine-tuned with generation loss" — is this the same module?
3. If Stage 2 trains cross-attention with Llama-2-70B, how is this used when inference is GPT-3.5?

**Impact:** Cannot evaluate whether the training-inference mismatch (Llama-2 → GPT-3.5) is valid.

**Required Fix:**
1. Explicitly name each cross-attention module (e.g., "Module A: Candidate Fusion", "Module B: Generator Integration")
2. Specify which modules are used at training vs. inference
3. Explain gradient flow: InfoNCE → gating head → source weights

---

### 🟡 Issue 4: Oracle Labeling Confound

**Location:** Section 3.4.1 (Oracle Generation)

**Problem:** Oracle labels are generated by asking GPT-3.5 "Does passage P help answer question Q?"

**Confound:** GPT-3.5 may already know the answer from parametric knowledge. If 40% of questions are "trivial" (LLM knows without context), the oracle labels conflate:
- Passage usefulness
- LLM parametric knowledge

**Required Fix:**
1. Run closed-book control: GPT-3.5 answers questions with NO context
2. Report what percentage are answered correctly
3. Filter these from oracle label validation
4. Re-report precision/recall on "non-trivial" questions only

## Should-Fix Issues (Strengthen Paper)

### Issue 5: Missing Baselines

The following recent methods are not compared:
- RT-RAG (reasoning-tree guided retrieval)
- CoopRAG (LLM–retriever cooperation)
- GenGround (generate-then-ground)
- SentGraph (RST-informed sentence-graph)
- HGRAG (hypergraph diffusion)

**Required:** At minimum, discuss in Related Work with trade-off analysis.

### Issue 6: Native-Config Baseline Comparisons

GraphRAG is designed for top-100 entities with summarization. Evaluating it at top-5 may be unfair.

**Required:**
- Report GraphRAG in both local and global modes
- Report iterative methods with their native context budgets
- Discuss trade-offs (latency vs. quality)

### Issue 7: FRAMES Evaluation Details

Missing:
- Which split used (train/dev/test)?
- EM/F1 exact definitions
- Any preprocessing or deviations from official protocol

### Issue 8: Passage Construction Transparency

How were 1.2M passages constructed?
- Source corpus?
- Segmentation strategy?
- Overlap with KG entities?

✅ **"Integrates three heterogeneous knowledge sources"** — Novel architecture
